## 一、全链路E2E端到端模板（V1 保留）

**来源**: DC-RJ-089（合并自 FLOW-001 + COMBO-018）| 本轮样本: TC-SJ-FLOW-001~003

**适用场景**: 验证多模块串行流水线的完整端到端业务流

**模板结构**:

```
### [编号] | [标题：从X到Y全链路验证]

**优先级:** P0 | **所属模块:** 全模块 | **测试类型:** E2E业务流程

**前置条件:** [列出所有必需的预置数据+系统状态]

**测试步骤:**
1. **[模块1名称]:** [操作描述] → 预期结果：[xxx]
2. **[模块2名称]:** [操作描述] → 预期结果：[xxx]
...
N. 发送/触发 [测试数据描述]
N+1. 逐环节验证：
   - [环节1] 的 [预期行为]
   - [环节2] 的 [预期行为]
   - [最终产出] 的 [预期状态]

**最终预期结果:** [一句话概括全链路正确运行的判定标准]
```

**关键特征**:
- 每个步骤标注所属模块，步骤间有明确的模块切换（"切换到XX Tab"）
- 测试数据有明确特征（如 severity=info），便于追踪数据在各环节的命运
- 预期结果精确到每条数据的处理结果，而非模糊描述
- 覆盖正向路径和负向分支（如丢弃/保留的分叉）

## 二、完整生命周期CRUD模板（V1 保留）

**来源**: DC-RJ-001（合并自 DATA-001 + FLOW-019）| 本轮样本: TC-SJ-FLOW-032~033

**适用场景**: 验证数据从创建到删除再到重建的完整生命周期

**模板结构**:

```
### [编号] | [XX完整生命周期（新增→编辑→使用→删除→重新添加）]

**优先级:** P0 | **所属模块:** [模块名] | **测试类型:** 数据生命周期

**前置条件:** 系统中无 [关键标识] 的资源

**测试步骤:**
1. 点击「新增」，填写 [关键字段值] → 保存
2. 列表中确认 [资源] 出现，所有字段值正确
3. 点击编辑，修改 [某字段] → 保存
4. 确认 [修改字段] 已更新，其他字段不变
5. [验证关联/引用关系]（可选的「使用」步骤）
6. 删除 [资源] → 二次确认
7. 列表中 [资源] 消失
8. 重新添加同一 [关键字段值] → 可成功添加（无残留）

**预期结果:** 创建/编辑/删除/重新添加全流程正常，数据无残留
```

**关键特征**:
- 覆盖 C→R→U→D→C 闭环，确保删除后无残留数据影响重建
- 包含「使用」环节，验证资源在业务上下文中的关联性
- 二次确认 + 列表消失 + 重建成功三步验证删除的彻底性

## 三、边界值测试模板（V1 保留）

**来源**: DC-RJ-007（合并自 PARAM-018~021）| 本轮样本: PA-03 TC-COLL-PARAM-012~015

**适用场景**: 验证字段的长度或数值边界约束

**模板结构**:

```
### [编号] | [字段名]-边界值

**优先级:** [P0/P1] | **所属模块:** [模块名] | **测试类型:** 边界值

**前置条件:** [打开对应操作入口]

**测试步骤:**
1. [字段] 留空（0值） → 保存 → 提示"不能为空"
2. [字段] 输入 [下边界值] → 保存 → 成功
3. [字段] 输入 [上边界值] → 保存 → 成功
4. [字段] 输入 [上边界值+1] → 保存 → 提示"不超过[X]字符"

**预期结果:** 边界值校验正确，[下边界]和[上边界]合法，[上边界+1]被拒绝
```

**关键特征**:
- 固定的 4 点测试模式：空/0 → 下边界 → 上边界 → 上边界+1
- 错误提示文案明确，与需求规格一致
- 每个边界值对应独立步骤，便于结果追踪

**适用场景**: 验证启用/禁用状态切换及功能联动

**模板结构**:

```
### [编号] | [规则类型]启用/禁用循环

**优先级:** P1 | **所属模块:** [模块名] | **测试类型:** 状态转换

**测试步骤:**
1. 禁用 → 确认操作 → 状态变为"已禁用"
```

## 六、过滤规则顺序执行模板（V2 新增）

**来源**: 本轮 FL-03（TC-SJ-FLOW-006~010）

**适用场景**: 验证多条规则按序依次匹配、首命中即终止的串行执行逻辑

**模板结构**:

```
### [编号] | 过滤顺序执行—数据[命中位置描述]

**优先级:** P0 | **所属模块:** [规则配置Tab] | **测试类型:** 集成测试

**前置条件:** 已按序创建 N 条规则：#1 [规则名]（条件=[xxx]，动作=[A]）、#2（条件=[yyy]，动作=[B]）、#3（条件=[zzz]，动作=[C]）

**测试步骤:**
1. 构造[场景名]数据：字段值同时/仅匹配 [规则#K]
2. 模拟发送数据 → 验证流经顺序：
   - #1：条件[匹配/不匹配]，执行[动作/跳过]
   - #2：条件[匹配/不匹配]，执行[动作/跳过] 或 [数据已终止于#K]
   - #3：[命中量无变化 / 收到数据]
3. 检查最终产出和后续环节状态

**预期结果:**
1. 数据按序匹配，首条命中后即终止（丢弃动作）或继续传递（保留/标记动作）
2. 明确验证截断效果：被丢弃数据不进入后续规则和下游环节
3. 未被命中的规则命中量不增加
```

**关键特征**:
- 每条规则的条件设计为互补/重叠，以验证「首命中优先」逻辑
- 覆盖 5 种命中模式：仅#1命中、仅#2命中（含截断）、仅#3命中、#1+#2同时命中（截断优先）、全不命中（直通）
- 截断验证是核心：通过后续规则命中量不变+下游环节不处理双重确认
- 每条数据都设计为精确匹配特定规则组合，预期结果可精确到每条规则的命中/跳过状态

## 七、归并窗口聚合模板（V2 新增）

**来源**: 本轮 FL-04（TC-SJ-FLOW-011~014）

**适用场景**: 验证基于时间窗口的分组聚合逻辑，包括窗口内合并、跨窗口独立、多分组隔离、窗口边界行为

**模板结构**:

```
### [编号] | 归并—[场景描述]

**优先级:** [P0/P1] | **所属模块:** 归并配置 | **测试类型:** 集成测试

**前置条件:** 归并规则已创建（相同字段=[F1,F2], 归并字段=[A1], 聚合方式=[计数/求和/去重/最大/最小], 时间窗口=[T]秒）

**测试步骤:**
1. [描述数据注入时序]：在T1/T2/...时刻发送 [N] 条数据，各条数据的 [分组键]=[值]，[聚合字段]=[值]
2. 等待窗口结束 → 检查归并结果
3. 逐条验证：归并后事件数、聚合计算结果

**预期结果:**
1. 同一窗口内同分组键的 [N] 条 归并为 [M] 条，聚合值=[预期值]
2. 跨窗口的同分组键独立归并（各自产出独立事件）
3. 不同分组键的归并互不干扰
4. [可选] 窗口边界数据归属按左闭右开/左闭右闭规则（记录实际行为）
```

**关键特征**:
- 明确时间窗口定义（秒/分钟），测试数据的时间戳间隔精确设计
- 覆盖 4 种子场景：同窗口多条合并、跨窗口独立、多分组隔离、窗口边界精确行为
- 窗口边界用例标记「待确认」，提示执行时需核对需求中的边界定义
- 聚合结果精确可验证（计数=3、求和=10 等数值，而非模糊描述）

## 八、弹窗取消三方式验证模板（V2 新增）

**来源**: 本轮 FL-14（TC-SJ-FLOW-040~042）

**适用场景**: 验证弹窗/对话框的多种关闭方式均不保存数据

**模板结构**:

```
### [编号] | 弹窗取消—[取消方式]不保存

**优先级:** P1 | **所属模块:** [模块名] | **测试类型:** 功能测试

**前置条件:** 打开[操作类型]弹窗，已填写完整数据但不保存

**测试步骤:**
1. 点击「新增/编辑」→ 填写所有必填字段（[关键字段]=[测试值]）
2. 通过 [取消方式] 关闭弹窗：
   - 方式A: 点击底部「取消」按钮
   - 方式B: 点击右上角「×」
   - 方式C: 点击弹窗外的遮罩层
3. 检查列表：[关键标识] 未出现，数据未保存

**预期结果:**
1. 弹窗正常关闭，无异常报错
2. 列表无变化（无新增/无修改记录）
3. 重新打开弹窗 → 表单为空（上次取消的数据已清空）
```

**关键特征**:
- 三种关闭方式逐一覆盖（取消按钮 / × / 遮罩层），而非仅测一种
- 删除/新增/编辑等所有弹窗类型通用
- 第三步（重新打开确认空表单）防止「假关闭但数据被缓存」的问题
- 步骤中明确写出测试值（如 IP=10.70.1.1），便于列表检查

## 使用建议

1. **E2E 模板** 用于最高优先级的全链路验证，每个需求至少 1 条
2. **生命周期模板** 用于每个独立数据实体（设备/规则组/规则），确保 CRUD 闭环覆盖
3. **边界值模板** 用于所有有长度/数值约束的字段，统一 4 点模式
4. **枚举完整性模板** 用于下拉/多选字段，不仅验证选项存在，更验证各选项的功能正确性
5. **状态流转模板** 用于有启用/禁用切换的规则类资源
6. **过滤顺序执行模板** 适用于所有「多条规则按序匹配、首命中执行」的场景
7. **归并窗口聚合模板** 适用于所有基于时间窗口的分组聚合场景
8. **弹窗取消三方式验证模板** 适用于所有弹窗/对话框的取消操作验证
